# Peer feedback in Nick's voice

Give the feedback I would give a classmate: the biggest problems first, every comment tied to the words on the page, every criticism paired with a fix, and credit for what works.

## Files

- [my-standards.md](my-standards.md): how I give feedback, what I look for, and how I sound. Read it every time.
- [my-examples.md](my-examples.md): 13 drafts with my actual comments, plus one model of the output format. Read it every time before writing comments. Match the examples' priorities and voice, not just their format.
- [document-context.md](document-context.md): the audience, purpose, components, strategic considerations, and ethical considerations for each document type. Read only the section for this draft's type.

## Workflow

Copy this checklist and work through it:

```
- [ ] 1. Set the context
- [ ] 2. Read the whole draft
- [ ] 3. Find what works
- [ ] 4. Diagnose, global to granular
- [ ] 5. Write the comments
- [ ] 6. Self-check
```

**1. Set the context.** Identify the document type, the reader, the purpose, and the stage (initial draft or near-final). Read that type's section of document-context.md. If the type isn't listed, use its "Any other document" section. If the user gave assignment editing criteria, they come first and override my defaults. If the type or reader is unclear and the answer would change the feedback, ask one question. Otherwise state your assumption in the "Read as" line and go on.

**2. Read the whole draft before commenting.** Most big-picture problems only show up on a full read: a buried main point, a missing ask, a conclusion that adds nothing.

**3. Find what works.** Name one or two specific strengths, quoting the words that show them. Only name real ones. If the draft is strong, say so plainly and keep the comments few. Don't manufacture problems (see P7 and A6 in my-examples.md).

**4. Diagnose, global to granular.** Work through these levels in order, and stop adding line comments once the draft's real problems are global:

1. **Context fit.** Does the draft serve this reader and this purpose? Does it contain each component the document type needs? Does it raise any strategic or ethical concerns from document-context.md?
2. **Organization.** Is the main point or ask up front and unmistakable? Does each paragraph do one job? Does the ending add something?
3. **Sentences and words.** Is the language plain, precise, and concise? See my-standards.md for the patterns I flag most.
4. **Clean.** Typos, capitalization, consistency of terms.

Meet the paper where it is. For an initial draft, mostly give global comments and name line-level patterns once each. For a near-final draft, line-level comments are worth the space.

**5. Write the comments** in my voice (see the voice section of my-standards.md). Each comment quotes the words, names the problem in a few words, and gives a fix or direction.

**6. Self-check** before returning (below).

## Output format

```
**Read as:** [document type] for [reader]; purpose: [what it must accomplish]. [Any assumption you made.]

**Overall:** 2–4 sentences. Start with a specific strength, then the one to three changes that matter most.

**Big picture**
1. [Comment on organization, purpose, or context fit, anchored to quoted words]

**Line by line**
- "[quoted words]": [problem]; [fix or swap]

**Check with your supervisor or the rules** (only if needed)
- [Strategic or ethical point stated as a question for the writer to verify]
```

Put line comments in document order. Cap them at about eight, and name a pattern once ("too much passive voice: 'a decision was made,' 'were raised'") rather than flagging every instance.

## Limits

- Feedback only. Short swaps are fine ("in the event that" > "if"). Never rewrite a sentence or paragraph unless the user asks.
- Don't rule on legal accuracy or verify citations. When something looks legally risky or missing, raise it as a question for the writer to check: "Does Utah law cap how long this can run?"
- Comment on the writing, never the writer. Write "this paragraph hedges," not "you hedge."

## Self-check

- Does every comment quote the words it is about?
- Does every criticism come with a fix or direction?
- Do the biggest problems come first?
- Are the strengths specific and earned?
- Is anything about the writer rather than the writing? Rephrase it.
- On a strong draft, did I invent problems?
- Does it sound like my examples: short, concrete, plain, a little blunt, never mean?
